# AnvilAutoTree

**铁砧工艺：这是棵树 / AnvilCraft: This Is a Tree**

给铁砧工艺（AnvilCraft）的超维存储和潜影集装箱增加自动补料。在 JEI 里用「+」快捷合成时，如果材料不够，会先确认、再按合成链在后台把缺失的物品造出来，最后自动把材料填进合成格。

- 目标版本：Minecraft 1.21.1 + NeoForge 21.1.x + AnvilCraft 1.6.x + JEI 19.x
- 许可：MIT

自动补料通过 JEI 为当前仓储菜单选出的处理器接入，补料结束后由该处理器回填。AnvilCraft 调整内部 JEI 处理器类名时，同一个 AnvilAutoTree JAR 可继续使用。

Minecraft 1.21.1 下的验证组合为 AnvilCraft `snapshot.2854`、`snapshot.2863`、`1.6.0+rc.1` 搭配 JEI `19.43.0.393`。AnvilCraft `snapshot.2854` 的原生转移使用新版 JEI 的 `TransferOperation.count()`，与 JEI `19.21.0.247` 搭配时缺少此接口。

## 使用流程

1. 打开已绑定的超维存储终端、潜影集装箱方块，或已连接集装箱的潜影终端。存储需要先解锁合成。
2. 在 JEI 查看工作台或切石机配方，点击配方旁的紫色「+」打开合成树。材料充足时也可以打开预览。普通「+」按 JEI 原有方式导入。
3. 服务端规划后，在当前存储界面上显示合成树。超维使用银灰面板和淡紫标题栏，潜影使用紫红面板和集装箱图标。红框标出缺口，窗口底部显示规划失败的原因。
4. 图标右下角的数字表示需求量，跟随图标缩放。大合成树默认从根节点开始显示，拖动或滚动可以查看屏幕外的分支。悬停节点可查看准确的数量。
5. 在确认按钮右侧输入 1–64 次。预览更新后，点击确认按钮或按空格提交。一次会补料并回填合成格，多次会执行目标配方并优先把成品放入当前存储。
6. 拖标题栏或边距移动窗口，拖四边或四角改尺寸。Ctrl + 滚轮围绕鼠标位置缩放，Shift + 滚轮横向滚动。「仅缺失」只保留有缺口或需要合成的分支。

## 自循环配方怎么处理

规划器维护一条「当前递归链」（祖先集合）。当某个物品在链上再次出现时，该候选配方立即判定失败并回滚，改试下一个候选配方；所有候选都失败时中止并提示「配方互为循环且无法打破」。

因此像「铁块拆成 9 铁锭、9 铁锭又合成铁块」这种互为原料的配方不会卡住：要么用存储里已有的另一方直接补齐，要么在检测到环后终止并给出明确提示。

## 配置

在「模组」列表中选择 **铁砧工艺：这是棵树 → 配置 → 客户端**。在预览里拖标题栏定位、拖边角改尺寸，然后点「保存布局」。临时移动游戏中的合成树只影响当前窗口。

`config/anvilautotree-common.toml`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `parallel` | `1024` | 超维每个服务端 tick 的合成次数上限。潜影取其 1/12，向下取整，最低 1 次，默认 85 次 |
| `maxDepth` | `16` | 合成链最大递归深度 |
| `maxSteps` | `256` | 单个合成计划允许的最大步骤数 |

并行度预留了扩展点：`CraftJobManager.setParallelismSource(ParallelismSource)` 可以让后续新增的物品或机制按玩家接管该数值（例如升级件提高并行度），无需改动作业执行逻辑。

## 支持范围

- 支持：工作台配方、切石机配方。
- 批量直接入库支持无容器返还的普通有序、无序及切石机配方。
- 不支持：需要熔炉、高炉、烟熏炉等其它机器才能得到的中间产物。这类缺口会中止并在确认界面/聊天栏中指出缺少哪个物品。
- 存储入口为超维存储终端、潜影集装箱和潜影终端。

## 实现要点

- **存储定位**：终端请求按玩家和虚拟坐标匹配 AnvilCraft 的存储视图。直接打开的潜影集装箱按所在维度、方块位置和交互距离校验。确认执行时重新检查存储 UUID。
- **读写**：两类存储共用物品处理器，写入经由 `onContentsChanged` 触发存盘和同步。远程存储成员改名时，按会话结构和方法签名查找。仓储菜单的位置接口或存储数据结构发生变化时，需要继续适配。
- **背包计入可用量**：规划时把玩家背包与存储一起算作可用（与 JEI 的缺料判定口径一致），扣料时先扣存储、不足再从背包补扣，避免多造玩家手上已经持有的那份。
- **规划与执行分离**：规划阶段只读存储，产出「子步骤在前」的批量步骤表；确认后才进入执行，每个 tick 按并行度推进，扣料失败会把已扣材料退回，产物放不下时退回玩家背包或掉落。
- **合成树侧边栏**：规划器在生成步骤表的同时生成 `CraftTreeNode` 树（每个节点记录需求量、当前库存、需要合成次数、是否补不齐与子节点），服务端把它 DFS 拍平成带父下标的 `CraftNodePayload` 列表随回执下发；客户端不再占用一个 `Screen`，而是由 `CraftTreeOverlay` 在 `ScreenEvent.Render.Post` 里叠加画在当前容器界面之上，用 `ScreenEvent.MouseButtonPressed/Released/Dragged/Scrolled.Pre` 拦下落在面板上的输入，面板外的一切点击照常传给底下的界面；当前界面是 JEI 自己的全屏配方界面时面板自动隐藏，避免挡住配方。
- **窗口化交互**：可拖四边或四角改尺寸，拖标题栏或面板边距移动窗口，拖树内容区平移（内容一屏放得下时可拖动窗口）。Ctrl + 滚轮缩放树，缩放比 = 自适应比 × 用户缩放。
- **缺失可视化**：规划器遇到补不齐的物品（没有配方或陷入自循环）时抛出 `MissingRecipeException`，异常在向上冒泡的每一层用 `under(...)` 把上层物品包成父节点，最终形成「根原料 → … → 真正缺失的物品」的断链；`plan()` 把这条断链挂进合成树，所以缺失物品直接以红框节点出现在树上，连同通往它的整条分支都看得见，面板底部只显示失败原因。规划失败时面板默认进入「仅缺失」视图、直接聚焦补不齐的分支；底部「仅缺失 / 全部」按钮通过 `markMissingBranch` 递归标记「自身是缺口、需要合成、或子树里有这类节点」的分支，只保留这几条。
- **JEI 占位**：通过 `IGlobalGuiHandler#getGuiExtraAreas` 上报可见的合成树区域。
- **JEI 转移**：支持附加按钮的 JEI 版本通过紫色「+」打开合成树，单份回填使用原处理器。旧版 JEI 沿用缺料时点击普通「+」、材料充足时 Alt + 点击的入口。
- **重放转移**：后台合成会改动存储，而客户端的存储快照是异步分页拉取的，因此转移会以 2 tick 间隔重试至多 80 次，避免「刚造好但快照还没刷新」导致的一次性失败。
- **超时保护**：等待规划回执或服务端接单超时会提示玩家。已经接单的批量合成可以继续运行至作业完成。

## 更新日志

### 1.0.2 · AnvilAutoTree 第二版

- 项目、模组 ID、资源命名空间和 JAR 统一采用 AnvilAutoTree。
- 保留砧库悬浮窗口、按需更新布局及底部按钮的立体阴影。
- 从旧版升级时，请移除旧 AnvilAutoCraft JAR，联机两端均使用新版。若要保留原设置，请将旧版 `anvilautocraft-client.toml` 和 `anvilautocraft-common.toml` 分别复制为 `anvilautotree-client.toml` 和 `anvilautotree-common.toml`。

### 前版 · AnvilAutoCraft 旧版系列

- 支持超维存储、潜影集装箱和潜影终端。潜影并行度为超维的 1/12。
- JEI 紫色「+」打开合成树。支持数量输入、空格确认、批量入库和可视化窗口设置。
- 合成树采用砧库浮窗，图标与数量同步缩放。
